Checklist principle

Robots QA is access and presentation logic.

Review page-level meta tags, response headers, bot-specific directives, and robots.txt together before release.

1. Export page-level robots directives

  1. Capture the final rendered HTML head for launch-relevant templates.
  2. Flag accidental `noindex` on pages that should be indexable.
  3. Confirm `nofollow`, `nosnippet`, `noarchive`, and `max-snippet` restrictions are intentional.
  4. Review staging, preview, test, QA, draft, and localhost rows separately.

2. Compare X-Robots-Tag headers

  1. Export response headers for HTML routes, PDFs, feeds, and downloadable files.
  2. Flag X-Robots-Tag `noindex` on launch URLs intended to be visible in search.
  3. Find headers that disagree with page-level meta robots values.
  4. Retest after CDN, middleware, or static host rules change.

3. Review bot-specific conflicts

  1. Compare generic `robots` directives with `googlebot` and `bingbot` directives.
  2. Flag cases where one bot receives `noindex` and another receives `index`.
  3. Document every intentional bot-specific snippet or cache restriction.
  4. Keep launch notes clear when directives differ by crawler.

4. Confirm robots.txt access

  1. Check whether robots.txt blocks launch pages that rely on meta robots directives.
  2. Remember that crawlers need access to the page to see page-level meta tags.
  3. Remove stale staging disallow rules before production launch when appropriate.
  4. Retest after robots.txt deployment and cache invalidation.
